STATUS Architecture not yet authorized. This is not a rejection — it is the correct first action. No automation decision is made until the process is documented and run manually.

Automation is premature for client onboarding document processing. The workflow branches on undocumented, per-client rules — exceptions are handled by memory, not by a defined path — so there is no stable baseline against which to assign any autonomy level. The process must be documented and run manually before the Gate is run again.

Stabilization checklist COMPLETE IN SEQUENCE

Do not advance to the next item until the current one is done.

01Document the current process step by step
No gaps, no "it depends." Name every step: what triggers it, who performs it, what they do, what they produce, what comes next.
02Identify every exception type
For each: what triggers it, who handles it, what they decide, what the possible outcomes are.
03Define the failure path
For each critical step: what happens on unexpected output, who is notified, within what timeframe, what the possible responses are.
04Establish a baseline
Run it manually and record: volume per cycle, frequency of deviations, exception rate per N runs, which steps produce the most variation.
05Run the documented process manually, N times, without deviation
N is set by volume — minimum 10–20 runs recommended; high-volume workflows use a statistically meaningful sample.
Re-evaluation criteria
✓Exception types documented with defined handling paths
✓Exception rate measured below a stated threshold over N cycles
✓Failure path defined for every step that can produce unexpected output
✓SOP followed without deviation for N consecutive runs
Earliest re-evaluation
After 30 consecutive days of documented manual execution and exception tracking — re-submit to the Gate with the completed SOP and baseline metrics.
Expected outcomes
BASELINE_RECORDEDOne manual execution completed and logged with inputs, steps, outputs, and exception notes
EXCEPTIONS_DOCUMENTEDA non-standard case occurred; exception captured with trigger, handler, decision, and outcome
RESUBMISSION_READY30-day baseline complete, SOP drafted, metrics compiled; ready for Gate re-assessment
BLOCKEDA run could not be documented due to missing exception context; log gap recorded, stabilization paused
ESCALATEDA case exceeded defined exception scope; routed to principal without SOP resolution
Autonomy Expires When

No autonomy is authorized while this plan is active. Reassess when the current process, exception paths, ownership, systems, policy, or evidence set changes; when the stabilization checklist is completed; or after any incident. Completion of the checklist triggers a new Gate assessment rather than automatic authorization.

No architecture options Architecture selection occurs at re-assessment. There is nothing to choose until the process is stable — this absence is intentional, not an omission.
